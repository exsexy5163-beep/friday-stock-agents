## 2. โครงเนื้อสเปก

| ส่วน | ต้องมีอะไร |
|---|---|
| **ขอบเขต** | รับอะไร · **ปฏิเสธอะไร** (เขียนให้เอเจนต์ "ตอบว่าอยู่นอกขอบเขตแล้วหยุด" ไม่ใช่พยายามทำ) |
| **Phase 0 — ดึงข้อมูล** | ดึงให้ครบก่อนเริ่มเขียน อย่าสลับไปมาระหว่างดึงกับเขียน · ระบุแหล่งและลำดับ tier ตาม CLAUDE.md §7 |
| **Phase 1 — โครงผลลัพธ์** | หัวข้อ/ตารางที่บังคับ · ฟอร์แมตการอ้างอิง · ฟิลด์ที่ **ห้าม** มี |
| **วินัยตัวเลข** | ห้ามคิดในหัว (ต้องรัน Python) · ตัวตั้ง/ตัวหารต้องเป็นประชากรเดียวกัน · ธง `[ไม่เปิดเผย]`/`[ข้อมูลไม่พอ]` แทนการเดา |
| **วินัยความเห็น** | อะไรพูดได้ (ผูกกับตัวเลขในหน้าเดียวกัน) · อะไรห้ามเด็ดขาด (ภาษาการลงทุน) |
| **Phase 2 — self-audit** | checklist ที่เอเจนต์ไล่เองก่อน return |

## 3. กติกาที่ใช้กับทุก agent ของ friday

- **agent ไม่เซฟไฟล์เอง** — return เป็นข้อความ ตัวหลักเซฟลง `outputs/<agent>/<TICKER>-YYYY-MM-DD.md`
  (ซ้ำวันเดียวกันเติม `-HHMM`)
- **ต้องมีเครื่องตรวจคู่กัน** `tools/<agent>_check.py` — ตรวจ **โครงสร้าง** ไม่ตรวจน้ำเสียง
  ออก `PASS` / `FAIL <เหตุผล>` · **ไม่ PASS ห้ามส่งให้ผู้ใช้**
- **interpreter:** เครื่องตรวจที่ต้องใช้ PyYAML → `.venv-utils/bin/python` ·
  งานคำนวณวิเคราะห์ → `.venv/bin/python` (CLAUDE.md §8) · **ห้ามใช้ `python3` ของเครื่อง**
- **ห้ามใส่ตัวเลขเคสตัวอย่างจริงลงในสเปก** — เอเจนต์อ่านสเปกก่อนทำงานทุกครั้ง = เห็นเฉลยก่อนอ่านงบ
  (บทเรียนจาก `bobby` รุ่นก่อน) ถ้าต้องเก็บผลการวัดไว้ ให้แยกไฟล์ออกไป `docs/` และห้ามเอเจนต์อ่าน
- **สร้าง agent ใหม่แล้วต้อง restart session** ก่อนถึงจะเรียกได้ — รายการ agent โหลดตอนเปิด session
