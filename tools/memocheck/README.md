## เพิ่มเอเจนต์ตัวใหม่

1. เขียน `profiles/<slug>.py` ให้มีตัวแปรชื่อ `PROFILE` เป็น `Profile(...)`
2. เติม slug ลงใน `KNOWN` ที่ `profiles/__init__.py`
3. ก๊อป shim จาก `tools/tommun_check.py` เปลี่ยนชื่อกับ `profile_slug`
4. สร้าง fixture ที่ `scratch/<slug>-check-fixtures/` (good ต้อง PASS · bad ต้อง FAIL รายกฎ)

> **ตารางในภาคผนวกจำแนกด้วย "จำนวนช่อง" ล้วน ๆ** — `TableSpec` สองตัวใน profile เดียวกัน
> **ห้ามมีช่วงจำนวนช่องทับกัน** ไม่งั้นแถวจะเข้าผิดกลุ่มเงียบ ๆ แล้วข้อความ FAIL จะชี้ไปผิดตาราง
> (โทนี่/ทอมมุนตั้ง `calc` เป็น `max_cols=None` ได้เพราะไม่มีตารางที่กว้างกว่า —
> ร็อบมีตารางคู่แข่ง 6 ช่อง จึงต้องล็อก `calc` ไว้ที่ `max_cols=5`)
>
> **ตารางที่กว้างที่สุดของ profile ก็ต้องล็อกด้วย** (แก้ 2026-09-01) — เดิมตารางคู่แข่งของร็อบ
> ตั้ง `max_cols=None` ทำให้มันกลายเป็น "ถังรับตก" ของทุกแถวที่กว้างตั้งแต่ 6 ช่องขึ้นไป
> แถวที่พิมพ์เกินเป็น 7 ช่องจึงถูกนับเป็นแถวคู่แข่งแล้ว PASS เงียบ ๆ
> **หลักที่ใช้ได้ทุก profile: `max_cols=None` ปลอดภัยเฉพาะเมื่อ profile นั้นตั้งใจรับตารางกว้างไม่จำกัดจริง ๆ**

**สิ่งที่ profile กำหนดได้:** รายชื่อ section · ฟิลด์ YAML ที่ต้องมี/ต้องห้าม · **ค่าที่ยอมรับของฟิลด์
คำตัดสิน** · **ความยาว list ที่บังคับ** · ช่วง section ที่บังคับบรรทัดปิดท้าย · บังคับ `(อนุมาน: ...)`
ด้วยไหม · section ที่เป็นภาคผนวก · ตารางในภาคผนวก (จำแนกด้วยจำนวนช่อง) · ตารางสมมติฐาน ·
**บรรทัดบังคับราย section** · ข้อความใน `--rules`

### `enum_yaml_fields` / `list_len_yaml_fields` — ตรวจ "ค่า" ไม่ใช่แค่ "มีคีย์ไหม"

เพิ่ม 2026-09-01 พร้อมกับแก้กฎ `1-yaml` ให้ **ค่าว่างนับเท่ากับฟิลด์ขาด**

เดิม `required_yaml_fields` ตรวจแค่ `key in meta` เท่านั้น ผลคือ `moat_rating: None` ·
`moat_rating_basis: ""` · `peers` ที่มีรายเดียว **ผ่านหมด** ทั้งที่ทุกตัวคือฟิลด์คำตัดสินที่ไม่มีเนื้อ
ตอนนี้แยกเป็นสามชั้น:

| ชั้น | จับอะไร | ใช้กับ profile ไหน |
|---|---|---|
| `is_blank()` ในแกน | `null` · `~` · สตริงว่าง · list/dict ว่าง ของ **ทุกฟิลด์บังคับ** | ทุกตัว อัตโนมัติ |
| `enum_yaml_fields` | ค่าที่ไม่อยู่ในรายการที่ยอมรับ | ร็อบ (`moat_rating` · `moat_trend`) |
| `list_len_yaml_fields` | list ที่ยาวไม่ตรงจำนวนที่บังคับ | ร็อบ (`peers` = 3) |

> **ระวังเรื่อง YAML `None`:** PyYAML อ่าน `None` เป็น **สตริง** `'None'` ไม่ใช่ null
> (null คือ `null` · `Null` · `NULL` · `~` · ค่าว่างหลังโคลอน) — กฎค่าว่างจึงจับ `None` ไม่ได้
> ต้องพึ่ง `enum_yaml_fields` เอกสารเก่าของร็อบเคยเขียนผิดตรงนี้แล้วทำให้เข้าใจว่ามีการตรวจอยู่

### สามฟิลด์ที่เพิ่มมาเพื่อเดมอน (2026-09-02) — และเหตุผลของแต่ละตัว

ทั้งสามตัวมี **ค่าตั้งต้นที่ไม่เปลี่ยนพฤติกรรมของ profile เดิม** (ยืนยันด้วยการ diff ชุดทดสอบ
ทั้ง 4 profile และ `--rules` ทั้ง 4 ตัว ก่อน-หลัง แล้วว่างทุกไบต์)

| ฟิลด์ | ค่าตั้งต้น | ทำอะไร | ทำไมต้องมี |
|---|---|---|---|
| `skip_verdict_rule` | `False` | ข้ามกฎ `3-verdict` ทั้งข้อ | เมโมประเมินมูลค่าต้องพูดคำว่า *มูลค่าเหมาะสม · upside · discount · margin of safety* เป็นเนื้องาน เปิดกฎไว้ = FAIL ทุกใบ |
| `allow_assumption_citation` | `False` | ให้ `[สมมติฐาน: ...]` นับเป็นที่มาที่ถูกต้องของกฎ `4-citation` | ตารางพยากรณ์อนาคตไม่มี filing ให้อ้าง การบีบให้ติด `[tier3]` คือการโกหกว่ามีแหล่ง |
| `stance_range_check` | `None` | คิดซ้ำด้วย `Decimal` ว่าฟิลด์คำตัดสินตรงกับ `ราคา` เทียบช่วง `ขอบล่าง–ขอบบน` ไหม (กฎ `1-yaml-stance`) | เมื่อปิด `3-verdict` แล้ว ฟิลด์นี้คือ **จุดเดียวที่เหลือ** ที่เครื่องตรวจยังจับ "ข้อสรุปที่เถียงกับตัวเลขของตัวเอง" ได้ |
| `threshold_flag_check` | `None` | `ThresholdFlagCheck(...)` คิดซ้ำด้วย `Decimal` ว่าฟิลด์ธงตรงกับช่วงของฟิลด์ตัวเลข และบรรทัดธงใน section ที่กำหนดพูดระดับ/ตัวเลขเดียวกับ YAML (กฎ `1-yaml-flag`, เพิ่ม 2026-09-23) | ธงคือผลลัพธ์หลักที่ผู้อ่านเห็น — ตรวจแค่ว่า "มีบรรทัดธง" ปล่อยให้ธงผิดระดับหรือหัวเมโมขัดกับเนื้อผ่านได้ (เจอจาก /scrutinize) |

> **⚠️ `skip_verdict_rule=True` แลกมาด้วยราคาที่ต้องรู้ตัว** — เปิดแล้ว **"น่าซื้อ" ·
> "แนะนำถือ" · "ราคาเป้าหมาย" จะผ่านเครื่องตรวจทั้งหมด** สิ่งที่เหลือกันการฟันธงมีแค่
> **บรรทัด DISCLAIMER บังคับใน `section_required_patterns`** กับวินัยในพรอมต์
> **ห้ามเปิดฟิลด์นี้ให้ profile อื่นเด็ดขาด** ถ้าไม่ได้ตั้งกลไกทดแทนไว้ก่อน

**เคสขอบที่ `1-yaml-stance` จัดการแล้ว** (ทดสอบครบใน `scratch/damon-check-fixtures/`):

- ฟิลด์ราคา/ขอบล่าง/ขอบบน **ไม่ใช่ตัวเลข** → FAIL พร้อมบอกว่าฟิลด์ไหน (ไม่ crash)
- **ขอบล่าง > ขอบบน** (ช่วงกลับหัว) → FAIL พร้อมโชว์ค่าทั้งคู่
- ค่าคำตัดสิน **นอกชุดที่ยอมรับ** → ปล่อยให้ `enum_yaml_fields` รายงาน **ไม่รายงานซ้ำ**
  (ถ้า profile ไหนตั้ง `stance_range_check` โดยไม่ตั้ง `enum_yaml_fields` คู่กัน
  กฎนี้จะรายงานเอง — จงใจ ไม่ให้ค่าพิมพ์ผิดหลุดเงียบ ๆ)
- ฟิลด์ใดฟิลด์หนึ่ง **ขาดหรือว่าง** → เงียบ เพราะกฎฟิลด์บังคับรายงานไปแล้ว

> **กฎ `9-assumption` นับ "บรรทัด" ไม่ได้นับ "สมมติฐานที่ต่างกัน"** — พอเปิด
> `allow_assumption_citation` ธงนี้กลายเป็นที่มาหลักของทุกแถวพยากรณ์ ทำให้ตารางสมมติฐาน
> ในภาคผนวกต้องยาวตามจำนวนแถวที่ติดธง (กริดความไว 5 แถว = 5 แถวในภาคผนวก)
> **นี่เป็นผลข้างเคียงที่รู้ตัวและยอมรับแล้ว** — พรอมต์ของเดมอนจึงเตือนว่าธงนี้ "เป็นของแพง"

### `section_required_patterns` — บังคับให้ "เขียนออกมา" สิ่งที่ตรวจตรง ๆ ไม่ได้

`{เลข section: [(regex, ชื่อที่แสดงตอน FAIL), ...]}` — ใช้กับกฎที่เครื่องตรวจไม่มีทางรู้เงื่อนไขจริง
แต่รู้ได้ว่ามีการเขียนถึงหรือเปล่า (กฎ `2c-required-line`)

ตัวอย่างที่ใช้อยู่ — สัดส่วนเงินสดของทอมมุน: สูตร ROIC ที่ล็อกไว้ไม่หักเงินสด เดิมพรอมต์สั่งให้
"เตือนเมื่อเงินสดเกิน 20% ของสินทรัพย์" ซึ่ง **ตรวจไม่ได้เลย** เพราะเครื่องตรวจไม่มีงบดุลในมือ
จึงเปลี่ยนเป็นบังคับให้ §5 ประกาศสัดส่วนเงินสด **ทุกเมโม** แล้วตรวจว่ามีบรรทัดนั้นไหมแทน
— เงื่อนไขที่ตรวจไม่ได้กลายเป็นข้อบังคับที่ตรวจได้ (แก้ 2026-09-01)

ตัวอย่างที่สอง — `POST_FILING_LINE` (ค่าคงที่ร่วมใน `core.py` ใช้ทั้งห้า profile, เพิ่ม 2026-10-09):
ภาคผนวกต้องมีบรรทัด `เหตุการณ์หลัง filing: <กระทบ|ไม่กระทบ|ไม่มี 8-K|ไม่มี 6-K>` โดยคำสถานะ
อยู่บรรทัดเดียวกับหัว (regex ใช้ `[ \t]` ไม่ใช่ `\s` กันข้ามบรรทัด · รับตัวหนาได้ทั้ง `**หัว:**` และ `**หัว**:`) — บทเรียน BWXT: เมโมห้าใบไม่มีใบไหน
เห็น 8-K ที่ประกาศขายธุรกิจ เครื่องตรวจรู้ไม่ได้ว่าอ่านจริงไหม (probe ในใบเสร็จทำหน้าที่นั้น)
แต่บังคับให้ "ประกาศผลการตรวจ" ได้ · test: `tools.memocheck.test_post_filing_events`

> ใช้ท่านี้เมื่อกฎสำคัญพอที่จะ FAIL ได้ แต่เนื้อหาจริงต้องอาศัยข้อมูลนอกไฟล์เมโม
> **อย่าใช้แทนการตรวจของจริงเมื่อตรวจของจริงได้**

### `forbidden_body_patterns` — คำต้องห้ามเฉพาะ profile (กฎ `3b-forbidden`, เพิ่ม 2026-09-23)

## กฎเหล็กเวลาแก้ `core.py`

รันชุดทดสอบของ **ทุก** profile ก่อนและหลัง แล้วผลต้องไม่เปลี่ยนโดยไม่ตั้งใจ:

```bash
for f in scratch/tony-check-fixtures/*.md;   do .venv-utils/bin/python tools/tony_check.py   "$f"; done
for f in scratch/tommun-check-fixtures/*.md; do .venv-utils/bin/python tools/tommun_check.py "$f"; done
for f in scratch/rob-check-fixtures/*.md;    do .venv-utils/bin/python tools/rob_check.py    "$f"; done
for f in scratch/adam-check-fixtures/*.md;   do .venv-utils/bin/python tools/adam_check.py   "$f"; done
for f in scratch/damon-check-fixtures/*.md;  do .venv-utils/bin/python tools/damon_check.py  "$f"; done
```

แล้ว diff `--rules` ของทั้งห้า profile เทียบก่อน-หลังด้วย — ผลต้องว่างทุกตัวที่ไม่ได้ตั้งใจแก้

> วิธีที่เร็วกว่าและใช้จริงตอนเพิ่มเดมอน: เก็บ **ทั้ง `--rules` และ exit code รายไฟล์**
> ลงไฟล์ก่อนแตะ `core.py` แล้ว `diff` ทีเดียวหลังแก้ — จับได้ทั้งกฎที่เปลี่ยนข้อความ
> และ fixture ที่พลิก PASS/FAIL โดยไม่ตั้งใจ
