# Portfolio Risk — จัดน้ำหนัก / ตรวจพอร์ตที่ถือ

| โหมด | ผู้ใช้ให้ | อาร์กิวเมนต์ของ optimize | หัวข้อ 08 ใน HTML |
|---|---|---|---|
| **หาน้ำหนัก** | รายชื่อ ticker + เป้า E(rp) | `--target 10` | เส้นเป้า-ความเสี่ยง + เทียบพอร์ตแบ่งเท่ากัน |
| **ตรวจพอร์ตที่ถือ** | สัดส่วน % หรือจำนวนหุ้นที่ถือจริง | `--weights T=% …` หรือ `--shares T=n …` (ห้ามใช้คู่กัน) · `--target` ไม่บังคับ | ตารางปรับพอร์ต (ถืออยู่ vs สัดส่วนเป้า) |

มิติความเสี่ยงแบบสมหมายออก **ทั้ง 2 โหมด** (heat map 1–5 · correlation · อุตสาหกรรม + เพดาน 35%/45% ·
ค่าเงินบาท ±5% ±10% + ช่วงวิกฤตคิดเป็นบาท · ดอกเบี้ย 10 ปี +1% · stress · สภาพคล่อง · เพดานเตือน 20%/30% ·
แนวทางลดความเสี่ยง)
เกณฑ์สีทั้งหมดอยู่ที่ `HEAT` ใน `scripts/risk.py` ชุดเดียว (HTML พิมพ์ตารางเกณฑ์ไว้ท้ายหน้า)

โหมดหาน้ำหนัก: สกิลหาน้ำหนักที่ **ความเสี่ยงไม่เป็นระบบต่ำสุด**
โดยยังได้ผลตอบแทนคาดหวังตามเป้า · ความเสี่ยงเป็นระบบ (ขยับตามตลาด) ลดด้วยการกระจายไม่ได้
จึงไม่ใช่สิ่งที่ตัวหาน้ำหนักพยายามลด — มันถูกกำหนดโดยเป้าผ่าน β แล้ว

**ตัวเลขทุกตัวที่ผู้ใช้เห็นต้องมาจาก `scripts/optimize.py`** — ห้ามคิดเลขเองในแชต ห้ามปัดใหม่

ไฟล์: `fetch.py` ดึงข้อมูล (รวมราคาปิด × volume 3 เดือน · DEXTHUS · DGS10 · อุตสาหกรรม Nasdaq) · `optimize.py` คำนวณ/โหมด · `risk.py` มิติความเสี่ยง
+ เกณฑ์สี + แม่แบบประโยค · `render.py` HTML (ย้ายมาจาก optimize.py)

## สูตร (บทที่ 8 · FN_08 จาก NotebookLM)

| สูตร | ความหมาย |
|---|---|
| 8.8 `E(rp) = Σ wᵢ E(rᵢ)` | ผลตอบแทนคาดหวังของพอร์ต |
| 8.9 `σ²p = w'Σw` | ความแปรปรวนของพอร์ต (รูปเมทริกซ์ของสูตร 2 หุ้น) |
| (12) `E(rᵢ) = r_RF + βᵢ (r_M − r_RF)` | CAPM — ใช้เป็น E(rᵢ) ของทุกตัว |
| single-index `Σ = ββ'σ²M + Σ_ε` | แยกความเสี่ยงเป็นระบบ/ไม่เป็นระบบ |

ตัวหาน้ำหนัก: **min w'Σ_ε w** ภายใต้ Σw = 1 · w ≥ 0 (ห้ามขายชอร์ต) · ไม่มีเพดานต่อตัว ·
β'w ≥ β เป้า (= E(rp) ≥ เป้า ภายใต้ CAPM) · Σ_ε เต็มเมทริกซ์ (นับหุ้นอุตสาหกรรมเดียวกันที่ residual สัมพันธ์กัน)

ที่มาของ input: r_RF = FRED `DTB3` ค่าล่าสุด (tier 1) · r_M = CAGR ของ SPY adj_close ย้อน 20 ปี
(ผู้ใช้กำหนดเองได้) · β/covariance = daily return 3 ปี เทียบ `^GSPC` ปีละ 252 วัน (ราคา yfinance tier 3)
· ค่าเงิน = FRED `DEXTHUS` (บาทต่อดอลลาร์ tier 1) · ดอกเบี้ย = FRED `DGS10` (tier 1) ·
อุตสาหกรรม = Nasdaq screener (tier 3 · การจัดกลุ่มแบบ Nasdaq ไม่ใช่ GICS · ETF หาไม่เจอ → "ETF / ไม่ทราบ")

## ขั้นตอน

### 0. ประตูก่อนเริ่ม
- **โหมดหาน้ำหนัก** ต้องมี **เป้า E(rp)** (% ต่อปี) และรายชื่อ ticker — ขาดอย่างใดอย่างหนึ่ง → ถามก่อน อย่าเดาเป้า
- **โหมดตรวจพอร์ต** (ผู้ใช้บอกว่า "ถืออยู่" / ส่งภาพหน้าจอพอร์ต):
  - อ่านภาพ/ข้อความ → ทำตาราง ticker + ค่า แล้ว **แสดงให้ผู้ใช้ยืนยันก่อนรัน** (อ่านภาพพลาดได้)
  - มีจำนวนหุ้น → `--shares` (ได้มูลค่า USD) · มีแค่ % → `--weights` (รายงานเป็น % อย่างเดียว) · มีทั้งคู่ → `--shares`
  - `--weights` รวมต้องอยู่ 99–101 (เศษจากการปัดในภาพ) · นอกช่วงนั้น STOP → ถามผู้ใช้ ห้ามเกลี่ยเอง
  - รายชื่อใน `--weights`/`--shares` ต้องตรงกับ `--tickers` ของ fetch ทุกตัว
  - เงินสด / กองทุนไทย / หุ้นนอกสหรัฐ ในพอร์ต → บอกผู้ใช้ว่าตัดออก แล้วคิดเฉพาะหุ้นสหรัฐ (น้ำหนักคิดใหม่จากส่วนที่เหลือ)
  - ข้อมูลพอร์ตอยู่แค่ในอาร์กิวเมนต์ของคำสั่ง **ห้ามเขียนลงไฟล์ใด ๆ**
- ticker ต้องเป็นหุ้นสหรัฐ (คลาสรองอย่าง `BRK.B` ได้) · มี suffix ตลาดนอก (`.BK` ฯลฯ) → บอกว่าไม่รองรับ
- ผู้ใช้ให้ r_M มาเอง → ส่งต่อด้วย `--rm` · ไม่ให้ → ใช้ค่าเริ่มต้น (SPY 20 ปี)
- ตั้ง `<slug>` = ชื่อที่ผู้ใช้ให้ ถ้าไม่มีใช้ `portfolio` · ไฟล์ปลายทางซ้ำวันเดียวกัน → เติม `-HHMM`

### 1–3. ดึง → คำนวณ → ลบ JSON (**คำสั่งเดียว**)
เครื่องมือรันคำสั่งล้างตัวแปรและโฟลเดอร์ปัจจุบันทุกครั้งที่ขึ้นคำสั่งใหม่ → **ห้ามแยก 3 ขั้นนี้เป็นหลายคำสั่ง**
(ถ้าแยก `$J` ในคำสั่งหลังจะว่าง แล้ว `rm` ไม่ลบอะไรเลย ไฟล์ที่มีรายชื่อพอร์ตจะค้าง) · ใช้ path เต็มทุกตัว
```bash
F=__FRIDAY_ROOT__; D=$F/scratch/portfolio-risk; J=$D/pr-$(date +%Y%m%d-%H%M%S).json
"$F/tools/marketdata/.venv/bin/python" "$F/.claude/skills/portfolio-risk/scripts/fetch.py" \
    --tickers AAPL MSFT JNJ --out "$J" \
  && "$F/.venv/bin/python" "$F/.claude/skills/portfolio-risk/scripts/optimize.py" \
    --in "$J" --target 10 --out "$F/outputs/portfolio-risk/<slug>-$(date +%F).html"
rc=$?; find "$D" -name 'pr-*.json' -delete 2>/dev/null
echo "exit=$rc json_left=$(find "$D" -name 'pr-*.json' 2>/dev/null | wc -l | tr -d ' ')"
```
- เติม `--rm 9.5` ท้าย optimize ถ้าผู้ใช้กำหนด r_M · `--target`/`--rm` เป็นตัวเลขล้วน **ไม่มี `%`**
- **โหมดตรวจพอร์ต:** แทน `--target 10` ด้วย `--weights AAPL=40 MSFT=35 JNJ=25` หรือ `--shares AAPL=10 MSFT=5 JNJ=8`
  (ใส่ `--target` เพิ่มได้ถ้าผู้ใช้อยากให้สัดส่วนเป้าใช้เป้าอื่น · ไม่ใส่ = E(rp) ไม่ต่ำกว่าพอร์ตปัจจุบัน) ·
  slug เริ่มต้น = `current-holdings`
- `fetch.py` ใช้ marketdata venv · `optimize.py` ใช้ root `.venv` (ห้ามสลับ)
- **ห้ามต่อ `| grep`/`| head` ท้าย optimize** — `rc` จะกลายเป็นรหัสของคำสั่งท้ายท่อ อ่าน `exit=` ผิด
- บรรทัด `find … -delete` ลบ `pr-*.json` **ทุกไฟล์** (รวมของรอบก่อนที่ค้าง) และทำงานเสมอไม่ว่าขั้นไหนล้ม
- **ต้องเห็น `json_left=0`** ก่อนตอบผู้ใช้ · ไม่ใช่ 0 → รัน `find` บรรทัดนั้นซ้ำแล้วเช็คอีกรอบ

**อ่านผลจาก `exit=`:**
- `exit=0` → stdout ของ optimize เป็น JSON สรุป (รวมกรณีถึงเป้าไม่ได้ `feasible: false`)
- `exit=2` → มีบรรทัด `STOP: …` ทาง stderr ไม่มี HTML → แจ้งข้อความนั้นตามจริง กรณีที่หยุด:
  - ไม่ใช่หุ้นสหรัฐ / ดึงดัชนีไม่ได้ (จาก fetch)
  - **ประวัติไม่ถึง 3 ปี** (วันแรกของราคาหลังวันเริ่มหน้าต่าง หรือมีข้อมูล < 95% ของวันทำการดัชนี) → บอกว่าตัวไหนขาด
  - **r_M ≤ r_RF** → CAPM กลับทิศ บอกผู้ใช้ และเสนอให้กำหนด r_M เอง
  - ดึง DTB3 / SPY ไม่ได้ · ตัวหาน้ำหนักหาคำตอบไม่ได้ · `--target`/`--rm` ผิดรูป
  - โหมดหาน้ำหนักไม่มี `--target` · `--weights`/`--shares` ผิดรูป ติดลบ ซ้ำ ไม่ตรงกับ `--tickers` ·
    `--weights` รวมไม่อยู่ 99–101 · `--shares` แต่ไม่มีราคาปิดล่าสุด
  - ห้ามตัดหุ้นที่ขาดออกเองแล้วรันต่อ — ให้ผู้ใช้ตัดสินใจ
  - ผู้ใช้เลือก "ใช้ข้อมูลเท่าที่มี" → รันใหม่พร้อม `--short-history <TICKER…>` ท้าย optimize
    (ต้องมี ≥ 252 วันทำการ) · β/Σ_ε ของตัวนั้นคิดทีละคู่จากช่วงที่มีข้อมูล คู่อื่นใช้ 3 ปีเต็ม ·
    กราฟ/ผลตอบแทนย้อนหลัง/ค่าเงิน/ดอกเบี้ยใช้ช่วงร่วม · stress ช่วงที่ตัวนั้นยังไม่เข้าตลาด = `[ข้อมูลไม่พอ]`
    ซึ่งทำให้ `risk_level` อาจต่ำกว่าความจริง (มิติร่วงช่วงวิกฤตหายไป) → ต้องบอกผู้ใช้
- ดึง DEXTHUS / DGS10 / อุตสาหกรรมไม่ได้ **ไม่หยุดงาน** — หัวข้อนั้นเป็น `[ข้อมูลไม่พอ]` + ขึ้นใน `flags`
  (บรรทัด JSON ของ fetch มี `fx_error` / `rates_error` / `sectors_error` / `sectors_missing` ให้ดู)
- `exit=` ค่าอื่น (เช่น 1 พร้อม traceback) → **บั๊กของสกิล** ไม่ใช่ข้อจำกัดของข้อมูล — บอกผู้ใช้ตรง ๆ
  ว่าสกิลล้ม แนบบรรทัด error สุดท้าย ห้ามคิดเลขแทนในแชต

### 4. สรุปในแชต (สั้น — รายละเอียดอยู่ใน HTML · ภาษาง่าย อธิบายศัพท์ครั้งแรก)
- path ของ HTML
- **ทั้ง 2 โหมด:** `risk_level` (ระดับรวม = แย่สุดของทุกมิติ) · `cap_warnings` · `sector_warnings` · `worst_crisis_dd` ·
  `effective_n` · `fx_usdthb` + `fx_windows` (ผลตอบแทนเป็นดอลลาร์ vs เป็นบาท) ·
  `rate_plus1_port` พร้อม `rate_r2_port` (r² < 0.10 → ต้องบอกว่าความสัมพันธ์อ่อน) · `hedges` (เล่าเป็นภาษาคนได้ แต่ **ห้ามแก้ข้อความในไฟล์ HTML** และห้ามเติมคำแนะนำนอกจากที่สคริปต์ให้)
- **โหมดตรวจพอร์ต:** `rebalance` (ถืออยู่ → สัดส่วนเป้า + ผล เพิ่มน้ำหนัก/ลดน้ำหนัก/คง) · `unsys_sigma` เทียบ
  `unsys_sigma_rebalanced` · `total_value_usd` + `total_value_thb` (ถ้าใช้ `--shares`) — ย้ำว่าเป็นผลคำนวณ ไม่ใช่คำสั่งซื้อขาย
- **โหมดหาน้ำหนัก:** ตามรายการด้านล่าง
- ตารางน้ำหนัก (จาก `weights` — รวม 100.00% แล้ว) · E(rp) · β พอร์ต · สัดส่วนความเสี่ยงเป็นระบบ/ไม่เป็นระบบ ·
  σ ไม่เป็นระบบเทียบพอร์ตแบ่งเท่ากัน · r_RF/r_M พร้อมที่มา
- `feasible: false` → พูดตรง ๆ ว่า **ถึงเป้าไม่ได้ ขาด `shortfall`** และตารางคือพอร์ตที่ E(rp) สูงสุดที่ทำได้
- `flags` ที่ไม่ว่าง และ stress ที่เป็น `[ข้อมูลไม่พอ]` → แจ้งด้วย
- ปิดท้ายด้วย disclaimer: เป็นการคำนวณจากข้อมูลในอดีตและสมมติฐาน CAPM ไม่ใช่คำแนะนำการลงทุน

## ข้อห้าม
- **ห้ามคำสั่งซื้อขาย** — ไม่เขียน "ควรซื้อ/ขาย" ตัวไหน รายงานเป็นผลคำนวณเท่านั้น · คำที่ใช้ได้มีแค่ที่สคริปต์ออก:
  เพิ่มน้ำหนัก / ลดน้ำหนัก / คง / เฝ้าระวัง (ในตารางปรับพอร์ตและแนวทางลดความเสี่ยง)
- **ห้ามแก้ข้อความใน HTML ด้วยมือ** — อยากเปลี่ยนถ้อยคำให้แก้แม่แบบใน `risk.py`/`render.py` แล้วรันใหม่
- เพดาน 20%/30% (หุ้นตัวเดียว) และ 35%/45% (อุตสาหกรรม) เป็น **คำเตือนใน HTML เท่านั้น** ห้ามใส่เป็นข้อจำกัดของตัวหาน้ำหนัก · ห้ามยอมให้ขายชอร์ต
- ห้ามเอา CAGR ในอดีตมาเป็น E(rᵢ) — แสดงไว้เทียบเท่านั้น
- ห้ามรันด้วย `python3` ของเครื่อง · `fetch.py` ใช้ marketdata venv · `optimize.py` ใช้ root `.venv` (ห้ามสลับ)
- ห้ามเติมไลบรารีหรือใช้ CDN — HTML เป็น SVG/CSS ในไฟล์เดียว
- ห้ามบันทึกรายชื่อพอร์ต สัดส่วน จำนวนหุ้น หรือมูลค่า ลงไฟล์อื่นใด (ชื่อไฟล์ HTML ใช้ slug ทั่วไป)

## ข้อจำกัดที่ต้องรู้
- β และ Σ_ε ประมาณจากอดีต 3 ปี (in-sample) อาจไม่คงที่ · ราคา tier 3 (yfinance)
- r_M 20 ปีอ่อนไหวต่อจุดเริ่ม-จบ · CAPM สมมติว่าตลาดชดเชยเฉพาะความเสี่ยงเป็นระบบ
- r_RF เป็นค่าวันนี้ แต่ r_M เป็นค่าเฉลี่ย 20 ปี (คนละช่วงเวลา) → ส่วนต่าง r_M − r_RF อาจต่ำกว่าจริง ทำให้ β เป้าสูงกว่าที่ควร
- σ ไม่เป็นระบบที่เทียบกับพอร์ตแบ่งเท่ากันเป็นค่า in-sample (ข้อมูลชุดเดียวกับที่หาน้ำหนัก) → พอร์ตที่คำนวณชนะโดยวิธีคิด ไม่ใช่หลักฐานอนาคต
- stress test ใช้น้ำหนักชุดปัจจุบันย้อนไปถือเฉย ๆ ในอดีต — เป็นภาพประกอบ ไม่ใช่การพยากรณ์
- สัดส่วนเป้าในตารางปรับพอร์ตมักกระจุกในตัวที่ residual ต่ำ (ถ้ามี ETF ดัชนีอย่าง SPY ในรายชื่อ มักได้เกือบ 100%)
  เพราะตัวหาน้ำหนักไม่มีเพดาน — เป็นผลของวิธีคำนวณ ต้องบอกผู้ใช้ตรง ๆ
- ETF นับเป็นก้อนเดียว ยังไม่มองทะลุไส้ใน (อุตสาหกรรม = "ETF / ไม่ทราบ" ไม่ใช้เพดาน) · สภาพคล่องใช้ราคาปิดจริง × volume เฉลี่ย 63 วันทำการ (tier 3)
- ความไวต่อดอกเบี้ย = ถดถอยรายสัปดาห์ตัวแปรเดียวกับ DGS10 ย้อน 3 ปี (≥ 52 สัปดาห์) → รวมผลที่ตลาดขยับตามดอกเบี้ย
  ไม่ใช่ duration ของหุ้น · r² มักต่ำ (หุ้นขยับด้วยหลายปัจจัย) · พอร์ต = Σ น้ำหนัก × ความไวรายตัว
- ค่าเงิน: สถานการณ์ ±5% ±10% คือ % เปลี่ยนของอัตราบาทต่อดอลลาร์ (มูลค่าเป็นบาทเปลี่ยน % เท่ากัน) ·
  วันที่ไม่มีค่าเงินใช้ค่าล่าสุดไม่เกิน 7 วัน · โหมด `--weights` รายงานเป็น % อย่างเดียว ไม่มีมูลค่าบาท
- แนวทางลดความเสี่ยง: อุตสาหกรรมเกิน 35% นับเป็นระดับ 4 · เกิน 45% นับเป็นระดับ 5 (เทียบเพดานหุ้นตัวเดียว)
